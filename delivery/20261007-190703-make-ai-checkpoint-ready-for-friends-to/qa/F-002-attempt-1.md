## Extra checks
These are not failures, but they could get a non-expert tester stuck.

- **Windows PowerShell `where uvx` (likely stuck point).** In PowerShell, `where` is an alias for `Where-Object`, so `where uvx` prints nothing and returns no error. The README says to run it "in PowerShell or Command Prompt". It only works in Command Prompt. Suggest `where.exe uvx` (works in both) or `(Get-Command uvx).Source` for PowerShell.
- **Opening the Claude Desktop config on Windows.** `%APPDATA%\Claude\claude_desktop_config.json` is cmd/Explorer syntax. In PowerShell the path is `$env:APPDATA\Claude\...`. A friend creating the file in Notepad may end up with `claude_desktop_config.json.txt`. The Microsoft Store build of Claude Desktop may keep its config under `%LOCALAPPDATA%\Packages\...`, not `%APPDATA%`. The easiest route on both OSes is Claude Desktop's Settings > Developer > Edit Config, which opens the right file. Consider mentioning it, and saying to paste `%APPDATA%\Claude` into the File Explorer address bar.
- **macOS.** `~/Library` is hidden in Finder, so "Edit Config" in the app, or `open ~/Library/Application\ Support/Claude` in Terminal, would help. On a Mac without Xcode command line tools, `git --version` pops up an install prompt, which is fine but worth a line. A Claude Desktop app launched from the Dock usually does not see `~/.local/bin`, so the full-path fallback will probably be needed on Mac. The README covers that case.
- **Unreplaced placeholder.** If the owner sends the README with `<owner>` still in it, uvx fails with a git error, `fatal: unable to access 'https://github.com/%3Cowner%3E/ai-checkpoint/': ... 403` (rc=1). This is expected given the criteria's placeholder, but the owner must replace `<owner>` and `<contact>` before sharing.
- **The 2-minute test name `tester/trial-1`.** If the model stores it as chat_name=tester and checkpoint_name=trial-1, `resume tester/trial-1` resolves (verified above). If it puts the whole string in checkpoint_name, save is rejected only if chat_name contains '/'. checkpoint_name allows '/' (model.py allow_slash), and resolve falls back to an exact checkpoint_name match, so either way works.
- **Launcher edge cases (code reading).** With an mcp version that is present but too old, the result is either an `ImportError` (cannot import name …), which is not caught and gives a traceback, or a `ModuleNotFoundError` for an `mcp.*` submodule, which shows the "install the extra" hint even though the extra is installed. Neither can happen with a fresh uvx install, which resolves `mcp` per pyproject.
- The uvx install builds from git, so the first launch needs git on PATH even before any checkpoint is saved. The README lists git as a prerequisite.
