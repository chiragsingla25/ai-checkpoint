## Extra checks
- **bash 3.2 / BSD static review.** I searched the script for `mapfile`, `readarray`, `declare -A`, `${x,,}`, `${x^^}`, `readlink`, `realpath`, `sed -i`, `mktemp`, `stat`, `date -d`, `|&`, `&>>`, `;;&`, `[[ -v`, `printf -v`, `${!`, `coproc` and `grep -P`, and found none. The script uses no arrays. The constructs it does use (`case`, `${v%%.*}`, `${v#*.}`, `{ ...; }` grouping, `command -v`, `pwd -P`, quoted heredocs inside a function, `sed -n 's/\(..\)/\1/p'` BRE, `head -n 1`) all work in bash 3.2 and on BSD. `"$*"` in `say` with no arguments is safe under `set -u` in 3.2. JSON merging is done in Python stdlib with no f-strings, so there is no `jq` dependency. I could not execute it under real bash 3.2 (see above).
- **shellcheck 0.11** (installed in a scratch venv) reports only SC1087 on `"$REPO_ROOT[mcp]"`. This is a false positive: the expression is a plain scalar followed by a literal `[mcp]` in every bash version, and the install worked. Writing `"${REPO_ROOT}[mcp]"` would silence the warning; this is cosmetic only.
- **Spaces in paths.** A repo at `.../My Projects/ai checkpoint`, run from `cwd=/`, gives rc=0. The config stores the spaced absolute command path, and the venv's `ai-checkpoint-mcp` answers `initialize`. A Desktop config path containing a space (the real macOS path has `Application Support`) also works.
- **`claude mcp add` failure.** A stub returning 3 for `add` gives `error: 'claude mcp add' failed` and rc=1. This is deliberate according to the build log, but note that on this path the Desktop config step never runs. It is not covered by a criterion.
- **Empty (0-byte) existing config.** The script treats it as `{}`: it writes a backup, writes the new file and exits 0. Strictly, an empty file is not valid JSON, but nothing is lost because the backup is written first. I count this as a reasonable reading of criterion 10 rather than a failure. The owner may want to confirm.
- **Non-ASCII values in other servers** are rewritten with `\u` escapes (`café ✓` becomes `café ✓`) because `json.dump` uses `ensure_ascii`. The values are semantically identical and the backup keeps the original. Cosmetic.
- **Old entry's extra keys are dropped.** The old `ai-checkpoint` entry's extra env (`X`) is gone after the update. This matches the criterion ("replaces only the ai-checkpoint entry").
- **Reused venv.** It is reused if `.venv/bin/python` is executable, with no check of which Python it was built with. A stale venv made with 3.9, or one left dangling after a pyenv version is removed, would show up as a pip failure under `set -e` (non-zero exit) rather than a tailored message. This is not covered by a criterion and is not observed here.
- **Symlinked script.** `REPO_ROOT` comes from `dirname "$0"`, so if someone symlinks the script elsewhere the repo root would be wrong. This is unusual usage.
