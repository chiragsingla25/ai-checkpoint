## Extra checks
These are notes only and do not affect the verdict.
- What a user sees: the table is short and readable. The fake scores are low (checkpoint 24% on invoice-sync) and the README says plainly that they only prove the pipeline works. Some key facts are very terse (`"rejected"`, `"not live"`, `"do not cite"`, `"pages"`). They suit a real judge but make fake recall noisy.
- The rendered checkpoint brief header reads `from checkpoint  (eval-chat/eval-checkpoint), saved at an unknown time in eval.` There is a double space because no checkpoint id exists in the eval. This is cosmetic.
- If the compaction reply is valid JSON nested deeper than Python's recursion limit (`{"a":` + `[`*100000 ...), `extract_json` raises `RecursionError`, which escapes `run_scenario`. The CLI catches only `CheckpointError`/`OSError`, so this would print a traceback. No real model would produce this, but catching `RecursionError` alongside `ValueError` in `_compaction_handover` would close it.
- If the judge reply is unusable (`garbage`), the probes are excluded: `probes_scored: 0`, recall `n/a`, no crash.
- A missing `--out` gives an argparse usage error with exit 2. An unknown `--model gemini` gives an argparse error with exit 2. If `--out` points at an existing file: `error: [Errno 17] File exists`, exit 1.
- The missing-key check runs after the scenario loads, so a bad scenario file is reported first. That seems fine.
- Real adapters were not exercised. No SDKs or keys are installed here, and the builder says the adapters were tested only against stubs.
